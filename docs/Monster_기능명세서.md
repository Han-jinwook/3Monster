- **문서 번호**: 3M-DOC-004

- **갱신 일시**: 2026-09-10

- **적용 범위**: 3Monster Hub 플랫폼, 웹 쇼룸, 결제 파이프라인, 라이선스 발급 엔진, 고객지원 시스템, 데스크톱 하위 앱 연동 규격

## 1. 개요 및 설계 원칙 (Overview & Architecture Principles)

본 문서는 3Monster 플랫폼의 모든 비즈니스 로직, 데이터 흐름, 접근 제어, 라이선스 발급 및 검증 파이프라인에 대한 **공식 기능 명세서**입니다.

### [원칙 1: UI/스타일링 배제 (No UI/CSS Specification)]
* 본 문서는 색상, 폰트, 여백, 컴포넌트 시각적 레이아웃 등 프론트엔드 스타일링 규격을 일절 포함하지 않습니다. (UI 관련 세부 사항은 `docs/Monster_UI_규정.md` 참조)
* 오직 비즈니스 규칙, 백엔드/클라이언트 상태 전환, API/DB 데이터 흐름, 보안 정책, 트랜잭션 수명주기만을 명세합니다.

### [원칙 2: 클라우드 기반 Source of Truth (Cloud-First Source of Truth)]
* 모든 사용자 권한, 라이선스 유효성, 결제 원장, 버전 관리는 Supabase Cloud DB를 최종 권위(Source of Truth)로 삼습니다.
* 로컬 캐시나 로컬 파일은 오프라인 비상 검증용 보조 수단으로만 사용되며, 서버 상태와 불일치 시 서버 데이터를 절대 기준으로 갱신합니다.

## 2. 사용자 역할 및 권한 통제 명세 (Roles & Access Guard)

### 2.1 사용자 역할 체계 (User Roles)
플랫폼 내 사용자는 4단계 역할 체계로 엄격히 통제됩니다.

| 역할 (Role) | 정의 | 권한 범위 |
| :--- | :--- | :--- |
| **`guest` (비회원)** | 로그인하지 않은 방문자 | 랜딩 페이지 열람, 쇼룸 둘러보기, 체험판(Trial) 다운로드, 공식 가이드 문서 열람 |
| **`user` (일반 회원)** | 계정 가입 및 로그인 완료 유저 (라이선스 미구매) | 비회원 권한 + 쇼룸 결제 진입 가능, 1:1 고객센터 문의 등록 가능 |
| **`buyer` (구매 회원)** | 1개 이상의 유효/만료 라이선스를 보유한 고객 | 일반 회원 권한 + 구매자 전용 대시보드 접근, 보유 라이선스 조회/연장, 재구매 자동 우대 혜택 |
| **`admin` (총괄 관리자)** | 플랫폼 총괄 운영자 | 전체 라이선스 수기 발급/정지/회수, 주문 원장 분석, 버전 배포, 고객센터 티켓 답변 |

### 2.2 역할 판별 및 동적 승격 알고리즘 (Role Resolution & Auto-Promotion)
`AuthContext`는 사용자가 로그인하거나 인증 상태가 변경될 때 다음 순서로 역할을 판별합니다.

1. **`users` 테이블 우선 조회**:
   - `users.email = current_user_email` 조회
   - 레코드가 존재하면 해당 레코드의 `role` 필드값(`admin`, `buyer`, `user`)을 부여합니다.
2. **`licenses` 테이블 폴백(Fallback) 조회 및 자동 승격**:
   - `users` 테이블에 명시적 역할이 없거나 조회되지 않는 경우, `licenses` 테이블에서 `contact = current_user_email` 조건을 만족하는 레코드가 1건 이상 존재하는지 확인합니다.
   - 1건 이상의 라이선스가 감지되면 즉시 역할을 `'buyer'`로 판정합니다.
   - 동시에 `users` 테이블에 해당 사용자를 `email: current_user_email`, `role: 'buyer'` 상태로 자동 `upsert`하여 계정 권한을 영구 승격 동기화합니다.
3. **일반 사용자 할당**:
   - 위 두 조건에 모두 해당하지 않으면 기본값인 `'user'` 역할을 부여합니다.

### 2.3 회원 전용 결제 가드 (Member-Only Checkout Guard)
* **비회원 결제 차단**: 비회원(`guest`) 상태에서는 상품의 '구매하기' 또는 '플랜 선택'을 통한 결제 모달 진입이 원천 차단됩니다.
* **자동 리다이렉트 및 복귀 처리**:
  - 미인증 사용자가 결제를 시도할 경우, 회원 전용 서비스임을 알리는 경고 후 로그인 페이지(`/login`)로 즉시 리다이렉트됩니다.
  - 이 때 현재 페이지 경로 및 선택 상품 쿼리를 `redirect` 파라미터로 보존(`navigate('/login?redirect=' + encodeURIComponent(currentPath))`)합니다.
  - 로그인이 완료되면 사용자는 이전 탐색 지점 또는 결제 시도 상품으로 자동 복귀하여 끊김 없는 구매 경험을 제공합니다.

## 3. 단일 이메일 고객 식별자 정책 (Email-Centric Identity & CRM)

### 3.1 식별자 단일화 원칙
* **불필요한 인적정보 수집 배제**: 상호명, 대표자 성함, 크몽 닉네임, 유선 전화번호, 휴대폰 번호 입력을 결제 및 회원가입 단계에서 전면 배제합니다.
* **이메일(`email`) 단일 식별자**: 모든 결제 승인 내역, PG사 통신, 라이선스 키 소유권, 기기 바인딩 내역, 고객지원 히스토리는 오직 이메일 단일 키를 기준으로 통합 관리됩니다.

### 3.2 결제 세션의 이메일 불변성 (Immutability of Buyer Email)
* 결제 모달(`PaymentModal`) 구동 시, 결제 수신자 이메일(`buyerEmail`) 필드는 현재 로그인된 사용자의 인증 세션 이메일(`user.email` 또는 `localStorage.user_email`)로 자동 강제 채움되며 **수정 불가능(ReadOnly)** 상태로 잠깁니다.
* 이를 통해 결제자와 라이선스 수령자 간의 이메일 불일치, 타인 이메일 오기입에 따른 라이선스 분실, 결제 어뷰징을 원천 차단합니다.
* 결제 PG사 필수 파라미터인 구매자명(`buyer_name`)은 사용자의 이메일 아이디 앞부분(로컬 파트) 또는 이메일 주소를 시스템에서 자동 전달합니다.

## 5. 라이선스 플랜, 가격 정책 및 재구매 우대 산정 (Licensing & Pricing)

### 5.1 플랜 등급 및 속성 구조

| 플랜 등급 (`license_type`) | 서비스 기간 | 정상 가격 | 재구매 할인가 | 추출 건수 한도 (`collection_limit`) | 용도 및 타겟 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`DELUXE`** (스탠다드) | 1개월 (30일) | 5,000원 | **4,200원** (16% 우대) | 1,000건 (`1000`) | 소규모 단기 타겟 추출용 |
| **`1M`** (디럭스) | 1개월 (30일) | 9,000원 | **7,600원** (15% 우대) | 무제한 (`NULL`) | 중급 마케터 표준 플랜 |
| **`3M`** (프리미엄) | 3개월 (90일) | 21,000원 | **17,900원** (15% 우대) | 무제한 (`NULL`) | 전문 대행사용 장기 특가 플랜 |

### 5.2 재구매 및 기간 연장 자동 우대 로직 (Automatic Repurchase Discount)
* **자동 감지 메커니즘**:
  - 사용자가 쇼룸에서 특정 제품을 선택했을 때, 사용자의 보유 라이선스 목록(`userLicenses`)에서 대상 제품과 정규화 키(`normalizeProdKey(product_id)`)가 일치하는 이력이 1건이라도 존재하는지 검사합니다.
  - 해당 제품을 과거에 구매했거나 현재 이용 중인 경우 `hasPurchased = true`로 자동 플래그 처리됩니다.
* **수동 조작 배제**:
  - 사용자가 '재구매 할인 적용' 버튼이나 체크박스를 수동으로 누를 필요가 없습니다.
  - 시스템이 기존 구매 고객임을 식별하는 즉시 결제 금액 산정 시 자동으로 재구매 우대가(스탠다드 4,200원 / 디럭스 7,600원 / 프리미엄 17,900원)를 적용합니다.
* **플랜 상태 표시**:
  - 현재 활성 라이선스를 보유한 고객의 경우 잔여 만료일(D-Day)과 현재 이용 플랜 명칭을 계산하여 표출하고, '기간 연장' 주문 프로세스로 자연스럽게 연계합니다.

### 5.3 1 PC 1 라이선스 HWID 바인딩 원칙 (Device Lock Policy)
* 모든 상용 라이선스는 `constraint_type: 'HWID'`로 발급됩니다.
* 사용자가 데스크톱 소프트웨어에서 최초로 시리얼 키를 등록하면 해당 PC의 메인보드/CPU 고유 하드웨어 식별자(HWID)가 Supabase `licenses.bound_value`에 영구 기록되고 상태가 `used`로 전이됩니다.
* 기 등록된 HWID와 다른 PC에서 동일 시리얼 키 입력을 시도할 경우 인증 엔진에서 `MISMATCH_HWID` 오류를 반환하고 실행을 차단합니다.
* 기기 변경(PC 교체)이 필요한 경우, 임의 변경은 허용되지 않으며 고객센터 문의를 통해 관리자가 이전 바인딩 값을 초기화(`bound_value: null`, `status: 'unused'`)해야만 재등록이 가능합니다.

## 6. PG 결제 연동 및 라이선스 자동 발급 파이프라인 (Payment & Fulfillment)

### 6.1 PG 연동 환경
* **PG 대행사**: NHN KCP
* **가맹점 코드 (Site Code)**: `ALRJ8` ((주)썬드림 2호 디지털 PG, sundreamer.app 공식 도메인 승인)
* **지원 결제 수단**:
  - `card`: 국내/해외 신용카드 및 체크카드
  - `bank`: 실시간 계좌이체
  - `phone`: 이동통신사 휴대폰 소액결제

### 6.2 결제 승인 및 라이선스 즉시 생성 트랜잭션 흐름
1. **결제 요청 생성**:
   - 클라이언트에서 결제 상품, 플랜, 인증된 구매자 이메일, 주문 고유번호(`ordr_idxx`)를 생성하고 KCP 스마트 페이 허브 스크립트(`kcp_spay_hub.js`)를 호출합니다.
2. **결제 승인 콜백 처리 (`handlePaymentComplete`)**:
   - PG 결제 모듈로부터 성공 응답 및 주문번호를 수신합니다.
3. **시리얼 키 자동 발급 규격**:
   - 형식: `CM-[4자리 영숫자]-[4자리 영숫자]-[4자리 영숫자]` (예: `CM-A7B2-9F1C-K8D3`)
   - 암호학적 난수 생성기를 사용하여 중복 없는 시리얼 키를 즉시 생성합니다.
4. **만료 일시 계산**:
   - 결제 시점(`now`)을 기준으로 선택 플랜의 기간(`currentTierInfo.months`)을 가산하여 ISO 8601 타임스탬프(`expire_date`)를 생성합니다.
5. **데이터베이스 레코드 기록**:
   - Supabase `licenses` 테이블에 다음 규격으로 즉시 `insert`를 수행합니다:
     * `product_id`: 매핑된 데스크톱 소프트웨어 식별자 (`NPlace-DB`, `CafeCrawler`, `AutoComment`, `EventStats`)
     * `license_type`: `selectedTier` (`DELUXE`, `1M`, `3M`)
     * `constraint_type`: `'HWID'`
     * `buyer_name`: 이메일 로컬 파트 (예: `buyer@domain.com` -> `buyer`)
     * `contact`: 구매자 이메일 주소
     * `channel`: `'3Monster (KCP 카드결제)'`
     * `serial_key`: 생성된 시리얼 키
     * `expire_date`: 계산된 만료 일시
     * `collection_limit`: 스탠다드 플랜은 `1000`, 무제한 플랜은 `null`
     * `status`: `'unused'` (프로그램 미등록 대기 상태)
     * `price_sold`: 실제 결제된 금액
     * `memo`: `[KCP 즉시결제] 주문번호: {ordr_idxx} | 결제금액: {finalPrice}원`
6. **사용자 역할 동기화**:
   - 구매자의 `users` 레코드를 조회하여 역할을 `'buyer'`로 즉시 승격 동기화합니다.
7. **클라이언트 완료 응답 및 전달**:
   - 발급된 시리얼 키, 만료일, 정식 다운로드 URL을 화면에 즉시 표시하며 원클릭 복사 클립보드 기능을 제공합니다.

  - 브라우저, 프록시, CDN에서 이전 구버전 압축 파일이 캐싱되어 오다운로드되는 문제를 원천 차단하기 위해, 다운로드 URL 생성 시 매번 현재 Unix 타임스탬프(`?t=Date.now()`)를 쿼리 파라미터로 강제 부착합니다.

### 7.2 바이너리 패키징 및 보안 규격 (Packaging Standard)
* **PyInstaller onedir 패키징 의무화**:
  - 단일 실행파일(`onefile`) 방식은 매 실행 시 임시 폴더에 압축을 해제하므로 앱 구동 지연과 백신 소프트웨어 오탐(False Positive)을 유발합니다.
  - 따라서 모든 상용 소프트웨어는 반드시 `_internal` 종속성 폴더와 메인 실행 파일로 분리되는 `onedir` 방식으로 빌드합니다.
* **PyArmor 난독화 필수 적용**:
  - 크롤러 코어, 라이선스 검증 모듈, DB 통신 모듈 등 핵심 비즈니스 로직은 빌드 파이프라인(`build_exe.py`)에서 무조건 PyArmor 난독화 및 바이트코드 암호화를 통과해야 합니다.

### 7.3 체험판 어뷰징(무한 루프) 방지 철칙
* **HWID 기반 `trial_logs` 영구 기록**:
  - 무료 체험판은 시리얼 키 없이 1회성으로 구동되며, 기기 HWID를 서버의 `trial_logs` 테이블에 기록하여 **기기당 생애 1회 50건 추출**으로 영구 고정합니다.
* **엔진 시작 전 강제 누적 사용량 동기화 (`_trial_baseline`)**:
  - 사용자가 로컬 SQLite DB나 설정 JSON 파일을 임의로 삭제/조작하여 무료 사용 한도를 리셋하려는 어뷰징을 방지하기 위해, 크롤러/수집 엔진이 구동되기 직전 반드시 Supabase 서버와 통신하여 최신 누적 사용량을 강제 동기화하고 기준선(`_trial_baseline`)을 재설정합니다.
  - 서버와의 통신이 실패하거나 누적 사용량이 50건을 초과한 경우 앱 동작을 즉시 중단합니다.

## 8. 고객지원(CS) 및 상태 동기화 메커니즘 (Support & Thread Sync)

### 8.1 문의 등록 시 구매자 권한 자동 바인딩
* 일반 사용자가 기술지원 게시판에서 문의를 작성할 때 입력한 이메일을 기반으로 `licenses` 테이블을 실시간 조회합니다.
* 해당 이메일로 유효한 라이선스가 확인되면 `licenses.contact` 이메일을 현재 문의자 계정과 즉시 바인딩하고, `users` 테이블의 권한을 `buyer`로 자동 승인 처리합니다.

### 8.2 관리자 답변 수정 시 실시간 알림 재동기화 설계
* **문제 배경**: 사용자의 문의 알림 수신 여부는 `localStorage`에 저장된 마지막 메시지 ID와 DB 상의 스레드 마지막 메시지 ID를 비교하여 판별합니다. 관리자가 기존 답변 내용을 수정할 경우 메시지 ID가 동일하게 유지되어 사용자 화면에 새 알림 배지가 활성화되지 않는 문제가 있었습니다.
* **해결 규격**: 관리자가 기존 답변을 수정하여 저장할 때, 해당 메시지 레코드의 고유 ID 뒤에 `-edited-{timestamp}` 접미사를 부여하여 고유 키를 강제 갱신합니다. 이를 통해 클라이언트가 새 메시지로 즉시 인식하고 읽지 않은 알림 배지를 실시간으로 활성화합니다.

### 8.3 단방향 라우팅 이벤트 기반 레이스 컨디션 방지
* URL 쿼리 파라미터(`?ticket_id=X`)와 React 상태(`selectedTicketForDetail`), 그리고 비동기 티켓 목록 로딩 간의 상호 충돌로 인한 화면 깜박임(Flickering) 및 자동 점핑 실패를 차단하기 위해, 무조건적인 State-to-URL 동기화 훅을 제거하고 명시적인 사용자 클릭 이벤트 핸들러(`useNavigate`)를 통한 단방향 내비게이션으로 처리합니다.

## 9. 관리자 주문 원장(Order Ledger) 및 라이선스 수명주기 관리 (Admin Operations)

### 9.1 고객 이메일 기준 거래 원장(Ledger) 집계 규격
관리자 라이선스 관리(`LicenseList.tsx`)에서 고객 이메일을 클릭하면 해당 이메일의 전체 결제 히스토리를 분석하여 다음 3대 핵심 KPI를 분할 산출합니다.

1. **제품수 (Product Count)**:
   - 해당 고객이 구매한 고유 제품 식별자(`product_id`)의 개수 (`new Set(products).size`)
2. **플랜수 (Plan Count)**:
   - 각 제품별 최초 구매 건수의 총합.
   - 라이선스 생성 일시(`created_at`) 기준 각 제품별 가장 오래된 첫 번째 결제 건을 신규 플랜 도입으로 집계합니다.
3. **연장 수 (Extension Count)**:
   - 각 제품별 2회차 이후의 재구매 건수, 또는 메모(`memo`) 및 판매 채널(`channel`)에 '연장' 또는 '재결제' 키워드가 포함된 건수의 총합.

### 9.2 라이선스 상태 전이 수명주기 (Lifecycle States)

```
[결제 완료 / 수기 발급]
         │
         ▼
     'unused' ──────── (타 기기 시도 시 거부)
         │
    (최초 HWID 등록)
         │
         ▼
      'active' / 'used' ──── (관리자 수기 정지) ────► 'suspended'
         │                                               │
    (만료일 경과)                                  (관리자 복구)
         │                                               ▼
         ▼                                           'active'
     'expired' ──── (기간 연장 결제 시) ────► 'active' (만료일 갱신)
```

| 상태 코드 (`status`) | 설명 및 동작 규격 |
| :--- | :--- |
| **`unused`** | 시리얼 키가 발급되었으나 아직 PC 프로그램에 등록(HWID 바인딩)되지 않은 대기 상태 |
| **`active`** | 정상 등록되어 유효기간 내에 있으며 프로그램 사용이 즉시 허용된 활성 상태 |
| **`used`** | 특정 기기(HWID)에 바인딩되어 정상 가동 중인 상태 |
| **`expired`** | 라이선스 만료일(`expire_date`)이 현재 시각을 초과하여 프로그램 인증이 차단된 상태 |
| **`suspended`** | 환불, 어뷰징, 계정 정지 등으로 인해 관리자가 강제로 소프트웨어 실행을 차단한 상태 |

## 10. 예외 처리 및 보안/이벤트 가드 규격 (Security & Safeguards)

### 10.1 모달 백드롭 클릭 닫힘 방지
* 결제 모달(`PaymentModal`) 및 주요 입력 폼 모달은 화면 바깥(Backdrop) 영역을 실수로 클릭하더라도 모달이 닫히지 않도록 이벤트 전파를 차단합니다.
* 사용자가 입력 중이던 데이터 유실 및 결제 진행 중 우발적 이탈을 원천 방지합니다.

### 10.2 로그인 화면 단축키 충돌 방지 및 안전 붙여넣기 (`Alt+V` 핸들링)
* 브라우저 환경에서 `Alt+V` 입력 시 브라우저 메뉴바(보기/View 메뉴)가 활성화되며 모달 포커스가 풀리거나 화면이 깜박이는 문제를 방지하기 위해 글로벌 `keydown` 이벤트를 가로챕니다.
* `e.altKey && (e.key === 'v' || e.key === 'V')` 감지 시 브라우저 기본 동작(`preventDefault`, `stopPropagation`)을 중단하고, 시스템 클립보드(`navigator.clipboard.readText`) 텍스트를 현재 활성화된 인풋 필드에 안전하게 주입합니다.

### 10.3 통신 타임아웃 및 네트워크 보안
* 모든 데스크톱 프로그램 및 웹 연동 모듈은 외부 Supabase 또는 PG사 통신 시 **고정 타임아웃(0.5초~3초)**을 엄격히 적용하여 무한 대기(프리즈)를 방지합니다.
* 로컬에 저장되는 라이선스 토큰 및 설정 데이터는 XOR 또는 AES 암호화로 보호하며 해시 서명 무결성을 검증합니다.
